# CIPMN October 2026 Examination Email Automation

## Scope

This automation supports candidates preparing for the October 2026 CIPMN Licensing Examination through AgileCert.

It extends the existing AgileCert communications architecture:

- `agilecert_communication_outbox`
- `agilecert_communication_events`
- `refresh_agilecert_communication_outbox(...)`
- `claim_agilecert_communication_outbox(...)`
- `agilecert-communications` Edge Function
- hourly GitHub Actions dispatcher
- Resend provider

The implementation must not create a parallel email system and must not change examination questions, attempts, grading, pricing, proctoring, certificates, or candidate access except where required to determine communication eligibility.

### Campaign expiry rule

A module becomes ineligible for preparation, purchase, payment-recovery, start, or resume reminders after its official examination date has passed.

The whole CIPMN examination-preparation campaign ends after 2026-10-18.

## Live catalogue reconciliation blocker

The live `CIPMN-MOCK` programme currently contains 18 published examination records.

The official timetable contains 17 modules.

Important mismatch found during the pre-activation audit:

- Official MOD-012: Managing Successful International Programs and Portfolios.
- Live `CIPMN-MOD-012`: Project Procurement and Contract Management.
- Live `CIPMN-MOD-EL06`: Managing Successful International Programs and Portfolios.
- EL06 does not appear on the official October 2026 timetable.
- Official EL04 is Project Procurement Management.

The campaign must not infer module identity from title alone. A controlled reconciliation must be completed before production activation.

## Action series

### 1. Examination preparation and countdown

Send relevant preparation reminders from campaign activation until the final examination.

Rules:

- Use official examination dates.
- Increase urgency as a module examination approaches.
- Never send preparation reminders after the module examination date has passed.
- Weekend modules are treated independently.
- Candidates should only be reminded about modules still relevant to them.

### 2. Failed-payment recovery

Identify unsuccessful or unresolved Paystack attempts using authoritative AgileCert order/payment state and verified provider status.

Relevant provider/payment outcomes include, where actually observed and verified:

- failed
- abandoned
- reversed
- voided
- cancelled

Rules:

- Continue recovery reminders until the related order becomes successfully paid/fulfilled.
- Stop immediately after success.
- Stop if the underlying official module examination date has passed.
- Do not mutate payment status merely to create a reminder.
- Do not rely on client-side payment state.
- Keep recovery idempotent by order/reference and cadence.

### 3. Unpurchased-module reminders

For each campaign candidate, compare paid/waived module access with the official still-upcoming timetable.

Rules:

- Personalize around modules still unpurchased.
- Do not advertise modules whose official examination date has passed.
- Stop reminders for a module after purchase/waiver.
- Do not count the live EL06 record as an official October 2026 module unless explicitly reconciled.

### 4. Mock examination activity reminders

Candidate/module communication state:

1. paid/waived but never started
   - send start reminder
2. started and incomplete
   - send resume reminder
3. some purchased modules complete, some untouched/incomplete
   - remind only for remaining purchased modules
4. completed
   - stop activity reminders for that module
5. official examination date passed
   - terminal expired state; stop all preparation/activity marketing for that module

Authoritative activity evidence should be derived from `exam_sessions` and `attempts`, not browser telemetry alone.

### 5. Monitoring copy

Every outbound email generated by this CIPMN campaign must send a monitoring copy to the approved IIPM monitoring address.

This must apply to:

- countdown/preparation
- payment recovery
- unpurchased-module reminders
- mock start reminders
- mock resume reminders

The monitoring address must be configured centrally and not hard-coded into individual templates.

Approved monitoring-copy recipient: `iipmnigeria@gmail.com`.

This address must be stored centrally in campaign/communications configuration and included on every CIPMN campaign email as a monitoring copy. It must not be hard-coded separately inside each email template.

## Deduplication and cadence

Every generated email requires a deterministic `event_key`.

Examples:

- `cipmn-prep:<candidate>:<module>:<cadence>`
- `cipmn-payment-recovery:<order>:<cadence>`
- `cipmn-unpurchased:<candidate>:<module>:<cadence>`
- `cipmn-mock-start:<candidate>:<module>:<cadence>`
- `cipmn-mock-resume:<candidate>:<module>:<cadence>`

Queued or failed messages must be cancelled automatically when their stop condition becomes true.

The hourly dispatcher may continue to run hourly, while the refresh function determines whether a message is due.

## Communication classification

Payment recovery and already-purchased examination-access/activity reminders are operational communications.

Unpurchased-module promotion and general optional preparation marketing must respect the appropriate optional communication preference/suppression controls.

The implementation must preserve existing unsubscribe and suppression behaviour.

## Audit and observability

Every queued, sent, failed, cancelled, delivered, bounced, complained, or converted communication must remain traceable through the existing communication outbox/event system.

Campaign metadata should include where applicable:

- official module code
- AgileCert examination id
- candidate id
- order id/reference
- campaign stream
- cadence
- official examination date
- reason the message was generated
- reason a queued message was cancelled

## Safety constraints

- Do not alter examination content.
- Do not alter question/answer data.
- Do not alter candidate attempts or grades.
- Do not change Paystack pricing or coupon logic.
- Do not change proctoring or integrity rules.
- Do not grant examination access without authoritative paid/waived entitlement.
- Do not send emails for expired official modules.
- Do not activate production delivery until reconciliation and dry-run evidence are complete.

## Approved cadence for dry-run validation

All times are Africa/Lagos (WAT). The hourly dispatcher remains unchanged; these rules determine `due_at`.

### Examination preparation/countdown

- 26 Sep through 5 Oct: one consolidated preparation email every 3 days at approximately 08:00 WAT.
- 6 Oct through 18 Oct: one consolidated preparation email each morning at approximately 07:30 WAT.
- Each email lists only official modules whose examination date has not passed.
- On a module's examination date, the module may appear only in the morning preparation message; it is excluded from all later campaign generations after that calendar date.
- After 18 Oct: no CIPMN October preparation email is generated.

### Failed-payment recovery

For a genuinely unresolved module purchase with no paid/waived replacement:

- first recovery: after the payment/order has remained unresolved for at least 1 hour;
- second recovery: 24 hours later;
- subsequent recovery: every 48 hours;
- when the official module examination is within 3 calendar days: at most once daily;
- stop immediately after paid/waived fulfilment;
- stop when the official examination date has passed.

Historical cancelled/expired attempts are ignored when a later paid/waived order exists for the same candidate and examination.

### Unpurchased modules

- one consolidated missing-module email every 72 hours while more than 3 days remain before the nearest missing module;
- once the nearest missing module is 3 days or less away: at most once daily;
- remove a module immediately when it becomes paid/waived;
- remove a module after its official examination date passes;
- unregistered official candidates receive registration/access guidance rather than a payment-state claim.

### Mock start/resume

- paid/waived but never started: remind every 48 hours;
- started but incomplete: remind every 24 hours;
- within 3 days of the corresponding official examination: at most once daily for either state;
- completed attempts suppress both start and resume reminders even if an older incomplete session still exists;
- stop after the official examination date passes.

### Candidate-level frequency guard

To avoid overlapping automation streams:

- maximum 2 CIPMN campaign emails to one candidate in any WAT calendar day;
- minimum 6 hours between CIPMN campaign emails to the same candidate;
- priority when multiple messages are due:
  1. payment recovery;
  2. mock resume;
  3. mock start;
  4. unpurchased-module reminder;
  5. general examination preparation/countdown.

Where practical, lower-priority module information should be consolidated into the higher-priority email rather than sent separately.
